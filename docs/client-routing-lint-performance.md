# 大规则集加载与 lint 评估（2026-11-12）

本轮先检查当前上限内的加载和完整 lint 成本，再优化覆盖判断。规则容量、
首条命中顺序、告警内容、`--strict` 退出码和保守证明范围均不改变。

## 改动

- 单个源匹配项直接判断覆盖，省去不必要的嵌套扫描。
- 大集合复用已加载的成员索引；精确域名、后缀、IP 和 CIDR 使用对应的覆盖证明。
- 覆盖 CIDR 时只检查不比目标更具体的源前缀；相邻小网段不会合并证明大网段。
- 精确域名不能覆盖整个后缀规则；IPv4/IPv6 保持区分，不为判断规则而查询 DNS。
- 相同共享集合、`all` 和不适用的协议/端口仍有短路路径。
- 保留原始线性实现作为测试参考，逐项比较告警及最早覆盖规则。

运行时成员匹配与 lint 覆盖证明是两种不同的问题。例如某个 IP 能匹配一个数值形式
的后缀，不会因此扩大 lint 对 IP 规则的证明范围。新增差分测试明确保护这个边界。

## 方法

Linux ARM64 Docker / Apple M1 Max，Rust 1.91.1；使用仓库 release 配置和
`CARGO_INCREMENTAL=0`，复用现有 Linux 构建卷。本轮没有重建本机增量缓存，也没有
修改全局 Cargo 配置、项目默认 profile 或依赖。

512 / 4096 项各 7 种场景：互不覆盖内联、第一条覆盖其余内联、等价集合反序、
父子后缀集合、CIDR 子网集合、最后一项不覆盖、同一集合四次引用。双集合场景中，
4096 是两份文件的合计项数（各 2048），符合现有资源限制。

每例独立进程，文件写入和配置构造后计时：文件加载/校验/索引构建、一次 Router
编译、5 次完整 lint 扫描。最终构建在同一进程中分别测优化实现与原线性参考，
并在计时前验证所有告警完全一致。下表为 5 次扫描的中位数，不是单请求 p95。

## 结果

| 4096 项场景 | 同二进制线性参考 | 索引覆盖分析 |
| --- | ---: | ---: |
| 4096 条互不覆盖的内联规则 | 34.433 ms | 30.774 ms |
| 第一条后缀覆盖其余内联规则 | 0.055 ms | 0.052 ms |
| 两份等价域名集合，顺序相反 | 5.134 ms | 0.043 ms |
| 父后缀集合覆盖子后缀集合 | 7.791 ms | 0.091 ms |
| /24 集合覆盖 /25 集合 | 11.245 ms | 0.029 ms |
| 最后一个目标不被覆盖 | 5.145 ms | 0.039 ms |

同一集合四次引用仍使用共享指针快速路径，通常低于 1 μs；原始数值见数据文件。
当前上限下，规则文件加载与一次编译仍是毫秒量级。该轮结果不构成生产启动时间、
网络吞吐或扩大容量的保证；主配置解析、终端/JSON 输出、冷存储和长期负载未计入。

独立重跑了 35 个运行时匹配案例；4096 项单集合尾部命中约 0.25–0.50 μs（批次平均
耗时的统计），没有观察到先前原型那种明显退化。仍不能把微基准换算成代理带宽。
原有索引基线中的源码哈希对应当时的构建；本次新增覆盖方法与测量另行记录。

[原始数据、二进制哈希和限制](benchmarks/2026-11-12-routing-lint.json)。文件来自写后
立即读取的临时目录；RSS 含测试夹具和分配器保留，不能作为索引独占内存。未固定
CPU 频率/亲和性或后台负载。数量上限不变，后续再评估更大列表和不同前缀分布。

## 复现与验证

```shell
CARGO_INCREMENTAL=0 cargo test --locked --release -p hysteria-cli --lib \
  routing::lint_performance_tests::measure_linux_release_routing_lint \
  -- --exact --ignored --nocapture
```

使用全限定名称和 `--exact`，避免 Cargo 子串过滤同时选中其他性能测试。普通测试
跳过这组测量。测试只使用临时文件和内存，不需要 NET_ADMIN，也不改变系统网络。

Linux release：174 项库测试通过（12 项显式测量/辅助测试忽略），37 项 CLI 合约、
4 项客户端转发、5 项路由工具测试及严格 Clippy 通过。本轮未执行本机完整 debug
构建，保留了已编译的本机二进制与依赖缓存。
