# v0.1.0-rc.6 — Pre-release

This release fixes IPv6 literal address handling on the server, including when
using a custom DNS resolver. Each executable contains both the client and server.

## Fixes

- Recognize a target such as `[2001:db8::1]:443` as an IPv6 address instead of
  sending the bracketed host to DNS. Previously, custom resolvers could return
  no address, causing TCP connections and UDP traffic to IPv6 literals to fail.
- Normalize valid IPv6 hosts for direct TCP/UDP outbounds, ACL matching and
  SOCKS5 address encoding. SOCKS5 now encodes IPv6 literals using its IPv6 address
  type. Host/port authorities still include the required brackets.
- Correct IPv6 resolver endpoint handling for DNS-over-TLS server names and
  DNS-over-HTTPS SNI overrides.

Domain names, IPv4 addresses and outbound address-family restrictions retain
existing behavior. Bracket removal is limited to valid IPv6 literals; malformed
hosts are not reinterpreted as valid addresses. IPv6 IP/CIDR ACL rules now match
literal targets correctly, so configured IPv6 routing rules can take effect.

## Validation

Seven new regression tests cover IPv6 normalization, SOCKS5 encoding, ACL IP/CIDR
selection, IPv6 TCP/UDP loopback traffic with custom UDP DNS, resolver bypass for
IP literals across system/UDP/TCP/TLS/HTTPS backends, and HTTPS resolver SNI.
The direct outbound test also checks that IPv4-only mode still blocks IPv6.

A local Linux x64 build with this fix was tested on jp2 with its existing
`resolver.type: udp` configuration pointing to `1.1.1.1:53`. Before the fix,
IPv4 TCP/UDP controls passed and IPv6 literal TCP/UDP failed. After the fix,
all four passed. Surge checks across all five jp2 entry ports passed 15/15,
covering IPv6 literal HTTP, ordinary HTTPS and UDP.

Release publication is gated on workspace tests and lint, vendored HTTP/3 and
QUIC tests, pinned Go/Rust interoperability, and all seven platform packages.

## Downloads

Prebuilt downloads cover Linux x64, ARM64 and ARMv7; macOS x64 and ARM64;
Windows x64 and ARM64. Every binary has an adjacent SHA-256 checksum. Linux
binaries require glibc.

The pinned Go interoperability baseline remains
`62d1016707af21b91e5fb6070311d9f016ff2754` with Go 1.26.5. The experimental
Chrome-shaped Rust client profile remains opt-in and does not enable ALPS.
