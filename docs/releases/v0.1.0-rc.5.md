# v0.1.0-rc.5 — Pre-release

This release fixes TUN UDP session handling under queue pressure and improves
failure diagnostics. Each executable contains both the client and server.

## Fixes

- Preserve an existing TUN UDP session when its packet queue is full. Drop the
  new datagram instead of replacing the session and interrupting queued traffic.
  Only a closed receiver permits session replacement. This path also avoids an
  extra copy of each datagram.
- Record TUN TCP connection and transfer failures, plus UDP session creation,
  send and receive failures. Error diagnostics are limited to one message per
  five seconds per TUN instance, with suppressed-error counts on the next message.
  Packet contents are not logged.
- Observe QUIC transport closure while idle and log the disconnect reason.
  Reconnection still occurs on the next proxy request; this release does not add
  a background reconnect loop or restore existing TCP streams.

## Validation and scope

Regression tests cover full and closed TUN UDP queues. Existing proxy tests now
exercise both IPv4 and IPv6 TCP/UDP targets, as well as peer-initiated QUIC closure
and subsequent reconnection across ordinary, obfuscated and port-hopping paths.

These tests do not establish the cause of reported IPv6 failures or prove
long-running TUN HTTP/3 stability. Application UI/helper state and log forwarding
must be handled in the integrating application.

Release publication is gated on workspace tests and lint, vendored HTTP/3 and
QUIC tests, pinned Go/Rust interoperability, and all seven platform packages.

## Downloads

Prebuilt downloads cover Linux x64, ARM64 and ARMv7; macOS x64 and ARM64;
Windows x64 and ARM64. Every binary has an adjacent SHA-256 checksum. Linux
binaries require glibc.

The pinned Go interoperability baseline remains
`62d1016707af21b91e5fb6070311d9f016ff2754` with Go 1.26.5. The experimental
Chrome-shaped Rust client profile remains opt-in and does not enable ALPS.
